# Demo — Usage Guide (isolated / from-scratch)

How to run this project on a clean machine, regenerate the API client, add new
endpoints, and drive the two Copilot agents. Nothing here depends on the original
client project — everything lives in this folder.

> For what the demo *is* (the pitch story, the tabs, the two agents) see
> [README.md](./README.md). This guide is the hands-on "how to run and extend it" doc.

---

## 1. What's in the box

```
genai-quickwins-demo/
├── api/                     Fake backend (zero dependencies, plain Node)
│   ├── openapi.json         The OpenAPI/Swagger spec — the single source of truth
│   └── server.mjs           Serves Swagger UI + /api-docs + the data endpoints
├── web/                     The React app (Vite + TS + AgoraDS)
│   ├── orval.config.cjs     How the typed API client is generated
│   └── src/api/generated/   ← GENERATED by orval. Never edit by hand.
├── .github/
│   ├── agents/              Copilot agents: @demo-frontend, @demo-frontend-reviewer
│   └── skills/              Skills the generator reads (style-guide, react-patterns…)
└── review/skills/           The reviewer's recipes + severity policy
```

Two processes run side by side:

| Process | Command | Port |
|---|---|---|
| Fake API (backend) | `node api/server.mjs` | **8099** |
| Web app (frontend) | `npm run dev` (in `web/`) | **5173** |

---

## 2. Prerequisites

- **Node.js ≥ 20** (built and tested on Node 24). Check: `node -v`.
- **npm ≥ 10** (ships with Node). Check: `npm -v`.
- Internet on first install (pulls `@ama-pt/agora-design-system` from the **public**
  npm registry — no private registry or token needed). The Swagger UI page also loads
  from a CDN; everything else works offline.

No global installs are required — `orval`, `vite`, `tailwindcss` are all local dev deps.

---

## 3. First-time setup

```bash
# from the project root
cd web
npm install          # installs React, AgoraDS, Vite, orval, tailwind…  (~1 min)
```

That's the only install step. The `api/` folder has **no dependencies** — it runs on
plain Node.

## 4. Running it (two terminals)

**Terminal A — the API (start this first):**
```bash
# from the project root
node api/server.mjs
```
You should see:
```
Fake Demo API on http://localhost:8099
  Swagger UI : http://localhost:8099/
  OpenAPI    : http://localhost:8099/api-docs
  Data       : http://localhost:8099/establishments?page=1&pageSize=10
```

**Terminal B — the web app:**
```bash
cd web
npm run dev
```
Open **http://localhost:5173/**. Open **http://localhost:8099/** for the Swagger UI.

> Order matters only for `npm run api:gen` (see §5). For just *running* the app, either
> order is fine — but the table stays empty until the API is up.

## 5. The orval workflow (the important part)

The typed React-Query client in `web/src/api/generated/` is **generated from the live
Swagger spec**, exactly like the real project (`orval` there reads `…:8083/api-docs`).
You never write `fetch`/`axios` calls by hand.

```bash
# 1. make sure the API is running (Terminal A) — orval reads from it over HTTP
node api/server.mjs

# 2. regenerate the client (Terminal B, in web/)
npm run api:gen
```

`npm run api:gen` runs `orval --config ./orval.config.cjs`, which:
- reads the spec from **http://localhost:8099/api-docs**,
- wipes and rewrites `web/src/api/generated/` (`clean: true`),
- emits one React-Query hook per operation (e.g. `useListEstablishments`,
  `useListInspections`, `useListEstablishmentNames`),
- routes every call through `web/src/api/mutator.ts` (the shared axios instance;
  base URL + array-param serialization live there).

> ⚠️ The API **must be running before `npm run api:gen`** — orval fetches the spec over
> HTTP. If it's down you'll get a connection error.

## 6. Adding a new endpoint or entity (the loop)

This is the cycle to grow the demo. Example: add a `licenses` list.

1. **Edit the spec** — `api/openapi.json`: add the path (`/licenses`), its query params,
   and the response schema (`License`, `LicensePage`). Follow the shape of `/inspections`.
2. **Serve the data** — `api/server.mjs`: add the in-memory rows and a route that filters
   server-side (copy the `/inspections` block). **All filtering stays on the server.**
3. **Restart the API** (Ctrl-C in Terminal A, then `node api/server.mjs`).
4. **Regenerate** — `cd web && npm run api:gen`. You now have `useListLicenses`.
5. **Build the page** — either by hand or with `@demo-frontend` (see §7), using the new hook
   + `DemoTable`. Add a tab in `web/src/App.tsx`.
6. **Verify** — `npx tsc -b && npm run build`.

## 7. Using the Copilot agents (VS Code)

Open the **project root** as the VS Code workspace (so `.github/` is at the top), then
reload the window (Command Palette → "Developer: Reload Window") so Copilot scans the agents.
Pick them from the `@` menu in Copilot Chat.

- **`@demo-frontend`** — the generator. Prompt it, e.g.:
  > *"create a filter page listing inspections, searchable by estabelecimento and resultado"*

  It reads the skills under `.github/skills/`, wires the orval hook, builds the page with
  AgoraDS inputs + `DemoTable`, and keeps filtering server-side.

- **`@demo-frontend-reviewer`** — the auditor (read-only, never edits). Point it at a file:
  > *"review web/src/features/inspections/InspectionsPage.tsx"*

  It cites the recipes under `review/skills/` and classifies findings 🔴/🟡 via the severity
  policy. Try it on `EstablishmentsPageDirty.tsx` to see it flag the staged violations.

## 8. Command reference

Run from `web/` unless noted.

| Command | What it does |
|---|---|
| `npm install` | Install dependencies (first time only). |
| `node api/server.mjs` | Start the fake API on :8099 (run from project **root**). |
| `npm run dev` | Start the web app on :5173 (hot reload). |
| `npm run api:gen` | Regenerate the typed API client from the live spec (API must be up). |
| `npx tsc -b` | Type-check — must report 0 errors. |
| `npm run build` | Production build (`tsc -b && vite build`). |
| `npm run preview` | Serve the production build locally. |

## 9. Troubleshooting

- **`EADDRINUSE: :::8099`** — something already holds the port. Find and stop it:
  - Windows (PowerShell): `Get-NetTCPConnection -LocalPort 8099 -State Listen | Stop-Process -Id { $_.OwningProcess } -Force`
  - or change `PORT` in `api/server.mjs` **and** the `baseURL` in `web/src/api/mutator.ts`
    **and** `input.target` in `web/orval.config.cjs` to match.
- **Table is empty / network errors in the browser** — the API isn't running, or it's on a
  different port than `mutator.ts` expects. Start `node api/server.mjs` and confirm
  `http://localhost:8099/establishments` returns JSON.
- **`npm run api:gen` fails with a connection error** — the API is down. Start it first (§5).
- **Filters don't narrow the list** — filtering is **server-side**; confirm the values reach
  the request (Network tab shows `?nome=…&estado=…`) and that the server route filters them.
  Array params must serialize as repeated keys (`paramsSerializer: { indexes: null }` in
  `mutator.ts`).
- **Copilot doesn't show `@demo-frontend`** — the workspace root must contain `.github/agents/`;
  reload the VS Code window after adding/renaming agents.
- **Swagger UI is blank** — it loads from a CDN; check internet access, or use the raw spec at
  `http://localhost:8099/api-docs`.
